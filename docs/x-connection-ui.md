# X connection UI candidate

Isolated source: `[local review checkout]`, based on `takt-connections-integrated-reviewed`. Not published or activated. No real credentials, grants, API credits, purchases, provider calls or posts.

## Implemented

- X-specific card reads `/api/providers/x/oauth/readiness`, never infers connectivity from the legacy general provider summary or callback query.
- Strict DTO validation and coherent capability/state checks. Missing configuration, unknown responses and errors keep actions disabled with a visible explanation.
- Separate explicit confirmation for official X authorization, one-time refresh and local removal. Scope/cost explanations and local-only removal semantics are visible. No reconnect or automatic refresh.
- Same-origin JSON transport, no-cache reads, abort/timeout handling and no redirect following. Authorization URLs pinned to official X endpoint, same-site callback, exact PKCE parameters/scopes, and bounded expiry.
- Mutation outcomes are followed by read-only status reload. Unknown results never cause automatic repeat. Double clicks, dismissal, leaving and old responses cannot create a newer UI outcome.
- Expiry invalidates stale connection evidence. Returning to the panel rechecks status; BFCache hooks use the existing panel lifecycle. Fixed callback outcome is removed from the URL and treated only as explanatory text.
- Existing setup details, focus restoration and responsive card style retained. Local preview exposes only the closed X handler with no runtime/policy/transport inputs; it cannot activate X.
